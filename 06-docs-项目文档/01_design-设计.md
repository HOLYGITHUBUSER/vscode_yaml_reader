# YAML Reader 产品与技术计划

> 状态：0.1.0 已实现并进入验证
> 日期：2026-07-30
> 目标平台：VS Code、Cursor、Remote SSH

## 1. 最终效果

打开任意 `.yaml` / `.yml` 文件后，可以通过编辑器标题按钮、右键菜单或 `Reopen Editor With...` 在主编辑区打开 `YAML Reader`。

它不是源码编辑器，也不是侧边栏大纲，而是一张完整的只读阅读页：

```text
┌──────────────────────────────────────────────────────────────────────┐
│ YAML Reader  搜索…  [深度 1] [全部收起] [在源码中打开] [更多]       │
├──────────────────────────────────────────────────────────────────────┤
│ 文档 1  › applications  ›  Nomi  ›  kits                            │
├──────────────────────────────────────────────────────────────────────┤
│ ▾  applications                                      map · 160 项    │
│ ┃  ▸  Nomi                                           map · 8 项      │
│ ┃  ▸  Launcher                                       map · 11 项     │
│ ┃  ▾  Settings                                       map · 6 项      │
│ ┃  ┃  ▸  kits                                        list · 14 项    │
│ ┃  ┃     owner                 "Team A"               string · L328  │
│ ┃  ┃     migrated             false                  boolean · L329 │
└──────────────────────────────────────────────────────────────────────┘
```

页面始终占用编辑器主区域，可以正常分栏、移动标签页和关闭，不占用左侧导航空间。

## 2. 视觉层次

层级通过四种信号同时表达，避免只靠颜色：

1. 每深入一级增加固定缩进。
2. 父子节点之间显示连续竖向引导线。
3. 映射、数组和标量使用不同图标与类型徽标。
4. 每一层使用低饱和度强调色，六级后循环。

暂定层级色板：

| 深度 | 强调色 | 用途 |
|------|--------|------|
| 0 | 紫色 `#8B5CF6` | 文档根与顶层领域 |
| 1 | 蓝色 `#3B82F6` | 一级分组 |
| 2 | 青色 `#06B6D4` | 二级分组 |
| 3 | 绿色 `#22C55E` | 三级分组 |
| 4 | 琥珀色 `#F59E0B` | 四级分组 |
| 5 | 玫红色 `#F43F5E` | 五级及循环 |

颜色只用于左侧引导线、展开箭头和轻量背景晕染，不整行涂成高饱和色。具体值会根据 Cursor 的深色、浅色和高对比度主题自动调整。

数据类型另用图标和徽标区分：

- `map`：蓝色六边形
- `list`：紫色层叠图标
- `string`：绿色 `Aa`
- `number`：橙色 `#`
- `boolean`：青色开关
- `null`：灰色空心圆
- `alias/tag`：琥珀色链接或标签

## 3. 默认折叠策略

- 默认展开深度：`1`。
- 打开文件时只显示文档根和一级业务分组，深层节点保持收起。
- 工具栏可以切换：仅根、深度 1、深度 2、深度 3、全部展开。
- 记住每个文件最近一次手工展开状态；文件结构大幅变化时回退到默认深度。
- 搜索时临时展开命中节点的祖先链，清空搜索后恢复原展开状态。
- “全部展开”对超大文件给出节点数量提示，但虚拟列表仍保证不会一次创建全部 DOM。

## 4. 阅读操作

### 4.1 导航

- 单击箭头：展开或收起。
- 单击节点正文：选中并更新顶部面包屑。
- 双击节点或点击行号：在源码编辑器中定位对应行。
- `↑` / `↓`：移动选中项。
- `←`：收起当前项或移动到父节点。
- `→`：展开当前项或移动到第一个子节点。
- `/`：聚焦搜索框。

### 4.2 搜索

- 同时搜索键、值、类型和 YAML 路径。
- 命中项高亮，并只展开“命中项 + 祖先链”。
- 支持 `key:`、`value:`、`type:`、`path:` 四种过滤前缀。
- 支持上一个/下一个命中项。

### 4.3 复制

- 复制当前值。
- 复制 YAML 路径，例如 `applications[3].kits[0].name`。
- 复制当前子树的原始 YAML。
- 复制操作不修改源文件。

## 5. VS Code / Cursor 集成方式

采用 `CustomReadonlyEditorProvider`，注册为可选编辑器：

- `Reopen Editor With... → YAML Reader`
- 编辑器标题按钮：`Open in YAML Reader`
- 文件右键菜单：`Open with YAML Reader`
- 命令面板：`YAML Reader: Open Preview`

扩展不会：

- 创建侧边栏面板；
- 默认接管全部 YAML 文件；
- 修改用户的默认编辑器关联；
- 写回或格式化 YAML。

用户体验稳定后，可以由用户自行选择“将 YAML Reader 设为 `.yaml` 的默认打开方式”。

## 6. 技术架构

```text
Remote/Local 文件
      │
      ▼
VS Code Extension Host
  - CustomReadonlyEditorProvider
  - 读取文件与监听变更
  - 打开源码并定位行号
      │ typed postMessage
      ▼
Webview 主编辑页
      │
      ├── Web Worker
      │    - YAML 解析
      │    - 多文档与锚点处理
      │    - 构建紧凑节点表
      │    - 建立搜索索引与源码区间
      │
      └── Preact UI
           - 工具栏与面包屑
           - 展开状态
           - 虚拟树列表
           - 主题与键盘导航
```

### 6.1 技术选型

- 扩展端：TypeScript + VS Code Extension API
- 阅读页：Preact + Vite
- 虚拟滚动：内置固定行高窗口算法（无额外运行时依赖）
- YAML 解析：`yaml`
- 测试：Vitest + `@vscode/test-electron`
- 扩展打包：esbuild + `@vscode/vsce`

选择 Preact 是为了保留组件化和现代 UI，同时让运行包比完整 React 更小。状态保持在少量 hooks 中，不引入大型状态管理框架，方便后续直接修改。

### 6.2 消息边界

Extension Host 与 Webview 只传递以下类型：

- `document/open`
- `document/changed`
- `source/reveal`
- `clipboard/write`
- `settings/changed`
- `error/report`

所有消息都使用可判别联合类型并在接收端校验，避免任意命令执行。

## 7. 大文件性能方案

针对当前已经超过 5,000 个 symbol/folding item 的 YAML：

1. 解析在 Web Worker 中执行，不阻塞界面线程。
2. 解析结果存成扁平节点表，不创建深层嵌套 JavaScript 对象副本。
3. 只计算当前展开分支对应的可见节点 ID。
4. 虚拟列表只渲染视口附近约 80～150 行。
5. 行高固定，滚动定位为 O(1)。
6. 搜索索引预先保存小写键、值、类型和路径，搜索不扫描 DOM。
7. 文件变化后做 250ms 防抖，并尽量恢复原展开状态。

第一版性能验收目标：

- 20,000 个节点的合成 YAML 可以成功打开。
- 初次打开到可操作目标不超过 2 秒。
- 任意时刻实际 DOM 树行数不超过 200。
- 展开、收起和滚动过程中不出现持续 100ms 以上的主线程阻塞。
- 深度 200 的 YAML 不崩溃，并能显示清晰错误或结果。

## 8. 安全与隐私

- 只读，不提供编辑、添加、删除或拖拽重排能力。
- 不发送网络请求，不使用 CDN，不加载远程字体。
- 不收集使用数据、文件名、路径或内容。
- Webview 使用 nonce 和严格 CSP。
- YAML 标签按数据展示，不实例化任意对象、不执行表达式。
- 解析失败时显示错误行列和附近源码，不静默降级成错误结构。

## 10. 实施阶段

### 阶段 1：扩展骨架

- 初始化 TypeScript、Vite、Preact、测试和打包配置。
- 注册只读自定义编辑器及三个打开入口。
- 建立严格 CSP 和双向消息协议。

验收：简单 YAML 能在独立编辑器页打开，关闭后不修改文件。

### 阶段 2：解析与节点模型

- Worker 中实现多文档 YAML 解析。
- 生成节点类型、路径、父子关系、值预览和源码区间。
- 显示语法错误、锚点、别名、标签和注释标记。

验收：测试样例的结构、路径和行号全部正确。

### 阶段 3：层级阅读界面

- 实现工具栏、面包屑、类型图标、深度配色和连接线。
- 实现默认折叠、深度切换、键盘导航与源码定位。
- 适配深色、浅色和高对比度主题。

验收：无需依赖颜色，也能明确辨认父子层级与类型。

### 阶段 4：大文件与搜索

- 接入虚拟滚动。
- 实现结构化搜索、祖先链展开和结果跳转。
- 加入展开状态恢复及文件变更防抖。

验收：20,000 节点性能测试通过。

### 阶段 5：打包与实机验证

- 运行类型检查、单测、集成测试和生产构建。
- 生成 VSIX。
- 安装到本机 Cursor。
- 安装到 `10.22.245.40` 的 Cursor Server。
- 使用当前 `应用侧Kit依赖_按应用分层_20260730.yaml` 验证真实效果。

验收：本地和 Remote SSH 都能稳定打开，源码文件哈希保持不变。

| 深度 200 | 不栈溢出 |

## 12. 第一版不做

- YAML 可视化编辑。
- 拖拽重排节点。
- 自动格式化或保存。
- Schema 校验和补全；继续交给 Red Hat YAML。
- 流程图、脑图或依赖关系图。
- Activity Bar、Explorer 或其他侧边栏入口。
- 云同步、账号体系和遥测。

这些限制让第一版首先成为一个稳定、安全、清晰的大型 YAML 阅读器。
